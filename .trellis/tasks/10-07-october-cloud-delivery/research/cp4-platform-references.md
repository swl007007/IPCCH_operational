# CP4 native trigger reference check

Read official public documentation on 2026-10-07; no GCP project inspection or resource mutation. These references support deployment-definition implementation, not proof that a trigger or job is deployed.

- [Execute a Cloud Run job using Workflows](https://docs.cloud.google.com/workflows/docs/samples/workflows-cloud-run-jobs): workflow receives `event`, reads `event.data.bucket` and `event.data.name`, filters before invoking a job and passes `body.overrides.containerOverrides[].env`. The sample uses the v1 connector; v2 is separately documented below. Add the approved exact request-path filter and generation binding; do not trigger on report/source writes.
- [v2 jobs.run connector](https://docs.cloud.google.com/workflows/docs/reference/googleapis/run/v2/projects.locations.jobs/run): call `googleapis.run.v2.projects.locations.jobs.run`, full `projects/{project}/locations/{location}/jobs/{job}` name and `body.overrides`. Connector waits for the long-running operation; default timeout 1800 seconds, configurable via `connector_params`. Workflow submission is not release success. Set a justified connector timeout or explicitly handle asynchronous submission; never infer durable run success from submission alone.
- [Route Cloud Storage events to Workflows](https://docs.cloud.google.com/eventarc/standard/docs/workflows/route-trigger-cloud-storage): direct event type `google.cloud.storage.object.v1.finalized`, JSON event content, event on object creation or new generation. The bucket must match the trigger's applicable project/location constraints; actual deployment configuration remains unverified.
- [Cloud Storage CloudEvent data schema](https://raw.githubusercontent.com/googleapis/google-cloudevents/main/jsonschema/google/events/cloud/storage/v1/StorageObjectData.json): `generation` denotes the object's content generation and is typed integer in this schema. Normalize the received exact generation to the positive decimal string expected by the CP1 contract; do not drop it or substitute latest-object lookup. Validate actual workflow payload behavior in the authorized cloud pilot.
- [Execute Cloud Run jobs](https://docs.cloud.google.com/run/docs/execute/jobs): basic CLI execution uses Cloud Run Invoker; configuration overrides require the documented stronger permission (the guide lists Cloud Run Developer). A workflow supplying request arguments/env therefore needs override authority, not merely an assumed invoker grant. Select explicit permissions sufficient for that operation when configuring the real deployment; do not invent project/service-account names.

Downloaded source snapshots for inspection were `/tmp/october-{workflows-jobs,storage-workflows,run-connector,run-execute}.html` and `/tmp/october-storage-event-schema.json`. Public URLs above are the durable references. Final release still uses object-store generation checks and the manifest-selected namespace; Cloud Run whole-task automatic retries must not imply in-place resume.
