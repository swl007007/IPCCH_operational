# Installed MLflow Gateway budget controls

Read-only inspection of MLflow 3.17.0, 2026-10-16. Let `M=/home/swl007007/projects/food-crisis-research/envs/mlflow-svc/lib/python3.12/site-packages/mlflow`. No service, credentials, database or cloud calls performed.

- Native USD monthly budget policies support GLOBAL/WORKSPACE/ENDPOINT/USER scopes and ALERT/REJECT actions (`entities/gateway_budget_policy.py:17-79`). Policy rows persist in SQL (`store/tracking/dbmodels/models.py:3396-3467`); REST create/get/update/delete/list/windows exist (`store/tracking/gateway/rest_mixin.py:652-674`, server handlers `7032-7092,7259-7284`). Endpoint policy target is the endpoint ID, user policy target is username.
- Accumulated spend backfills from gateway traces' total_cost (`gateway/budget.py:33-98`, `store/tracking/gateway/sqlalchemy_mixin.py:1408-1453`). Default tracker is per-process memory, refreshed every 600 seconds; optional Redis exists but is not required infrastructure for this proposal. This is not an independent durable reservation ledger.
- **Admission checks already incurred spend only.** `gateway/budget.py:173-203` accepts no estimated cost/token quantity; `gateway/budget_tracker/in_memory.py:146-147` rejects when cumulative_spend >= budget_amount. `gateway/budget.py:220-238` records cost after completion and catches recording errors. Supervisor directly inspected these paths. Concurrent or expensive last requests can overshoot; policy failures can continue without enforcing the intended budget.
- `gateway/tracing_utils.py:225-226` returns the provider function unchanged when usage_tracking is false, so completion cost recording does not run. It defaults false on endpoint config. Enable and verify tracking if relying on these supporting policies; trace loss/deletion or absent pricing is not zero cost.
- Gemini maps max_tokens/max_completion_tokens to maxOutputTokens (`gateway/providers/gemini.py:34-48,148-152`), but request schema only imposes ge=1 (`types/chat.py:251-254`). No endpoint output ceiling or in-flight semaphore was found in installed gateway/SQL endpoint config. Legacy YAML slowapi limits are request-frequency limits and do not prove equivalent SQL-backed behavior.
- Gemini usage maps candidatesTokenCount to completion_tokens, leaving thoughtsTokenCount in extra metadata (`gateway/providers/gemini.py:381-404`, directly inspected). Base provider and pricing use completion_tokens as output tokens (`gateway/providers/base.py:371-394`, `tracing/utils/__init__.py:376-403`). Billable thinking-token coverage therefore needs verification with the actual selected model. Installed model catalog prices are not current Google quotes.

Implementation implication under design.md: native REJECT policies can provide supporting signals, but alone do not meet the required durable accumulated-cost admission, bounded concurrent calls and missing-price/state failure behavior. Use only the small application guard the approved design allows, with the existing PostgreSQL store, pinned model/pricing and conservative request bounds; avoid adding Redis or a separate gateway merely for this research service. Account for all provider calls in a multi-step assistant response and retain conservative reservations after uncertain outcomes. An overall Gateway policy cannot represent SQL/storage/Cloud Run costs.
