# MLflow artifact transport findings

Read-only installed-code exploration, 2026-10-16. This is implementation guidance, not cloud acceptance. Let `S=/home/swl007007/projects/food-crisis-research/envs/mlflow-svc/lib/python3.12/site-packages`.

- GCS implements MultipartUploadMixin, but not StreamUploadMixin or MultipartDownloadMixin (`S/mlflow/store/artifact/gcs_artifact_repo.py:37`). Uvicorn's ordinary upload stages the complete file before GCS transfer (`S/mlflow/server/artifact_router.py:160-174`); download also stages the complete file before streaming it to the client (`:95-124`). Supervisor directly read both branches. Cloud Run writable temporary storage must be included in memory sizing; chunked Python I/O alone does not remove staging.
- Native signed multipart upload exists, but `generate_signed_url` receives neither service_account_email nor access_token (`gcs_artifact_repo.py:235-272`, directly inspected). Ordinary metadata ADC does not implement Signing; adding signBlob permission alone does not make this implementation use remote signing. Impersonated Signing credentials are a possible future option, not required infrastructure for currently observed small files.
- MLflow 3.17 can auto-discover multipart upload capability when its enable environment variable is unset (`mlflow_artifacts_repo.py:145-194`). It defaults to a 500 MiB threshold and 10 MiB chunks (`environment_variables.py:691-706`). Do not assume the nominal False environment default prevents automatic capability discovery. GCS does not support signed multipart downloads in this implementation.
- Scout scanned package manifest sizes and cross-checked stat sizes: maximum observed package member was 9,748,410 bytes, `forecast-compact_climate_global_weather_oracle_03--compact_global_2026_extension/weights/2026/model_phase2_worse.ubj`. Package count grew 91 to 103 during inspection; the maximum was unchanged. This is a changing build snapshot, excludes other historical MLflow artifacts, and is not a complete capacity result.
- Minimal candidate: keep package directories and upload individual files through authenticated proxy + GCS. Do not merge them into giant archives or add signing infrastructure without evidence of need. Before deployment, measure the complete artifact inventory's largest files, chosen concurrency and actual upload/download limits. Acceptance must test real service transfer under configured RAM/timeout limits. Future multi-GiB single-file support is not established; direct GCS access would also change the current authenticated-proxy user contract and must be reviewed if needed.

No cloud request, IAM change, upload, download or provider call was made by this exploration. Detailed route and signing findings came from scout `/root/mlflow_artifact_transport`; the supervisor directly spot-checked staging and signed-URL call sites.
